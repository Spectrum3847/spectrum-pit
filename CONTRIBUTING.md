# Contributing to Spectrum Pit

Thanks for your interest. This repository is a release mirror, which changes the mechanics a little.

## How changes flow

- The team develops in a private repository. Every published release is synced here as one squashed commit with no internal history, so this repository and the private one share no git history at all.
- Pull requests here are reviewed by the maintainer. If a PR is accepted, the maintainer turns it into a patch and applies it to the private repository under your original commit author (name and email), then opens an ordinary internal PR there to run the private CI and land it on the private trunk.
- Because of that, **this PR is closed rather than merged** once the change lands privately. The code does not disappear: it ships in the next release, which syncs back here as part of that release's squashed commit, still carrying your authorship.
- Keep PRs self-contained to code under `lib/`, `test/`, `android/`, `ios/`, `linux/`, `macos/`, `windows/`, `web/`, `pubspec.yaml`, and `firestore.rules`. `README.md`, `CONTRIBUTING.md`, `LICENSE`, and everything under `.github/` in this mirror are generated by the sync from the private repository's own separate copies and cannot be patched back the same way. If one of those needs a change, open an issue instead of a PR.

## Before you open a PR

- Toolchain: Flutter 3.47.1 / Dart 3.13.1.
- Run the same gates CI runs:

```bash
flutter pub get
dart format --output=none --set-exit-if-changed .
flutter analyze --fatal-infos
flutter test
```

- Keep changes small and focused, one concern per PR.
- No emojis anywhere: code, comments, docs, commit messages, or UI strings. Use plain text, or Material icons in UI.
- UI changes should keep the existing visual system: the palette tokens in `lib/src/theme/pit_palette.dart`, IBM Plex type, flat surfaces, and 8px corners for standard components (12px for sheets and dialogs).
